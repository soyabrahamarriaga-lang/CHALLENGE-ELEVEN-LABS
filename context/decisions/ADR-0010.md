# ADR-0010: conversación individual con el agente ElevenLabs existente

- Fecha: 2026-10-03
- Estado: aceptada; amplía ADR-0008 y sustituye la ausencia de conexión ElevenLabs descrita en ADR-0009 únicamente para la conversación individual
- Autor: Codex; operador: soyabrahamarriaga-lang
- Evidencia: el usuario proporcionó ID y API key local y eligió expresamente «Conversación individual con el experto».

## Problema y decisión

Conectar UserHelper con el agente existente sin exponer la API key ni confundir una conversación con la sala del equipo o con captura de conocimiento validado. Adoptar el SDK oficial `@elevenlabs/client`: voz mediante token temporal WebRTC, texto mediante URL firmada WebSocket. El backend fija el agente y reutiliza origen autorizado, consentimiento, código de equipo y límite de intentos. No requiere credenciales de LiveKit Cloud para la conversación individual.

El SDK inicia captura dentro de `startSession`, antes de devolver un objeto que pueda cerrarse; no ofrece un aborto público de esa preparación. Ejecutarlo en un documento del mismo origen montado bajo demanda permite retirar todo su contexto al cancelar, terminar o navegar, incluyendo permisos pendientes. El padre valida ventana, origen e identificador en los mensajes; no persiste accesos ni conversaciones. Se documenta la necesidad de verificar el comportamiento de permisos y medios en los navegadores de entrega.

## Alternativas y consecuencias

- Incorporar el agente a la sala LiveKit: requiere puente/worker y difusión compartida; fuera de la elección individual del usuario.
- ID público directamente en frontend: no establece una barrera de acceso propia. Se eligen accesos temporales del backend; esto no cambia la visibilidad configurada en el proveedor.
- SDK en el componente principal: simplifica el montaje, pero hace depender la cancelación durante un permiso pendiente del retorno asíncrono del SDK. El iframe añade una segunda entrada al build y un protocolo acotado.
- Sustituir el agente o prompt remoto: innecesario para el alcance autorizado; se conserva la configuración existente.

La inspección confirmó autenticación obligatoria desactivada en el proveedor y retención de audio activada. Se documentan ambos hechos y el consentimiento informa transmisión y posible conservación; no se modifica privacidad remota. Descartar mensajes de UserHelper no borra los datos conservados en ElevenLabs. El código compartido no es autenticación por persona. La conversación nueva no promete continuidad de contexto con otra sesión.

La UI conserva la biblioteca sintética. El SDK no recibe pantalla ni ejecuta herramientas de cliente; no hay Work Map automático. Una frase del agente que prometa observar no constituye evidencia de observación implementada. Los mecanismos de eliminación de evidencia y derivados del challenge siguen pendientes.

## Ontología

Se añaden conversación del agente y mensaje de conversación. Se distingue configuración disponible de conexión activa; hablar o transcribir no equivale a capturar razones validadas, ni una conversación equivale a un Work Map. La conversación individual no pertenece a la sala LiveKit del equipo. El esquema mantiene versión 1.

## Validación y relevo

Accesos reales para WebRTC/WebSocket emitidos y conversación por texto respondida por el agente. Pruebas del contrato de acceso y del protocolo; build y harness. Los resultados exactos están en la entrada del aporte y docs/ELEVENLABS.md. Voz física, comportamiento de permisos, visión y Map/Teach siguen pendientes. Esta rama parte de `codex/livekit-calls` porque reutiliza su backend, aún en PR #5; se publica un PR dependiente sin integrar la base automáticamente.
