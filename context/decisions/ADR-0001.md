# ADR-0001: Memoria compartida y atribución por aporte

- Fecha: 2026-10-03
- Estado: aceptada para la base de colaboración
- Autor: Codex; operador: soyabrahamarriaga-lang
- Evidencia: solicitud del usuario de contexto compartido, decisiones y coordinación con Claude entre computadoras.

## Decisión y razón
Versionar instrucciones, estado, ontología, ADRs y entradas JSON independientes en el mismo repositorio que el código. Cada commit añade una entrada con actor, operador, tarea, archivos, decisiones, validación, análisis ontológico y relevo. Los nombres usan UTC y un sufijo aleatorio para reducir colisiones. Las entradas confirmadas son inmutables; una corrección añade otra entrada.

## Alternativas
Un único log Markdown provocaría conflictos frecuentes. Mantener todo en chats no permite que otro equipo recupere el contexto desde GitHub. Introducir una base de datos externa añade infraestructura innecesaria para el arranque.

## Consecuencias
La memoria viaja con los commits. Existe trabajo documental por aporte. La autoría del agente es declarada y diferenciada del operador autenticado; no es una firma criptográfica. No se registran razonamientos internos privados ni conversaciones completas.

## Impacto ontológico y verificación
Distinguir actor, operador, aporte, decisión y evidencia de los conceptos propios del producto. `actors.json` y las entradas preservan esa atribución; el harness comprueba campos, referencias y cobertura de archivos. La calidad de las explicaciones requiere revisión humana.
