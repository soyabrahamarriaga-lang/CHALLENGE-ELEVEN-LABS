# ADR-0012: Visión de pantalla mediante el LLM multimodal del agente ElevenLabs

- Fecha: 2026-10-03
- Estado: aceptada (protocolo verificado; captura en la UI pendiente)
- Autor: Claude; operador: soyabrahamarriaga-lang
- Relación: amplía ADR-0010; la bóveda de ADR-0011 conserva las transcripciones resultantes

## Problema y evidencia
Capture exige que el agente pregunte en pausas sobre algo visible en pantalla (CAP-01/02/03). El usuario pidió que el propio agente de ElevenLabs vea la pantalla y descartó usar una API de visión aparte. Inspección por API del agente «Observador de procesos»: el LLM `qwen35-397b-a17b` no aceptaba imágenes (`supports_image_input=false`); `file_input` habilitado con máximo 10 archivos por conversación. El catálogo `/v1/convai/llm/list` ofrece LLMs con imagen. El SDK `@elevenlabs/client` 1.26.0 expone `uploadFile` (`POST /v1/convai/conversations/{id}/files`) y `sendMultimodalMessage`.

## Alternativas
- Modelo de visión separado (Claude/GPT/Gemini por API propia): requiere otra clave; descartado por el usuario.
- Frames cada 1–2 s al agente: imposible con el límite de 10 archivos, y cada imagen es un turno de usuario que provoca respuesta; interrumpiría al experto.
- `contextual_update` con descripción textual: no transporta imágenes; necesitaría visión externa.

## Decisión y razón
El usuario configuró él mismo el agente (no se modificó por API): LLM `claude-haiku-4-5` con entrada de imágenes y un bloque de prompt para mensajes `[PANTALLA mm:ss]`: comparar con la captura anterior, una sola pregunta breve sobre el cambio que revele razón o límite, «Mm-hm.» si no hay cambio relevante, y debrief con ≥3 preguntas nuevas y teach-back al terminar.

El cliente enviará una captura **solo en una pausa** (pantalla que cambió y luego quedó estable), máximo 10 por conversación: cada envío es una oportunidad de pregunta situada, coherente con la cadencia de 3–5 preguntas/10 min del brief. `scripts/agent_vision.mjs` fija el formato del mensaje; `npm run check:vision` lo verifica contra el agente real.

## Consecuencias
- Coste por imagen en créditos ElevenLabs; latencia de Haiku por turno.
- La detección de pausa es por estabilidad visual, no por teclado o lectura en otras apps; un experto que lee sin mover nada puede recibir una pregunta. Debe explicarse en la demo (Apprentice Test 1).
- Las capturas se suben a ElevenLabs y quedan sujetas a su retención (ADR-0010). Usar solo datos ficticios/sandbox hasta definir redacción (Presidio) y borrado.
- Los campos de Data collection para el Work Map aún no existen en el agente: el Work Map automático depende de que se creen.

## Impacto ontológico
`screen_event` se materializa como captura enviada al agente en una pausa con su minuto; la pregunta del agente es una hipótesis de oportunidad, no evidencia de intención. Sin cambio en `ontology.json` todavía: se actualizará cuando la UI registre capturas como evidencia en la bóveda.

## Verificación
Conversación real por texto con el agente (datos ficticios): captura 1 (4711 opex) → «Mm-hm.»; captura 2 (0400 capex) → «¿Por qué cambiaste el centro de costos de 4711 a 0400?». Reproducido con `npm run check:vision`. Resultados en la entrada del aporte.
