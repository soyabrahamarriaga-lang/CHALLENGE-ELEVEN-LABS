# ADR-0016: El tutor aprende de la bóveda Obsidian mediante su base de conocimiento en ElevenLabs

- Fecha: 2026-10-04
- Estado: aceptada
- Autor: Claude; operador: soyabrahamarriaga-lang
- Relación: usa la bóveda (ADR-0011) y las notas de proceso de PR #14/#17; tutor de PR #16

## Problema y evidencia
El usuario pidió que «el tutor debe conectarse a la base de conocimientos del Obsidian» y eligió la base de conocimiento de ElevenLabs frente a inyectar contexto al iniciar. El brief (p. 5–6) propone que el Work Map pase a la base de conocimiento y Procedures del tutor. El agente «Tutor de procesos» (`claude-haiku-4-5`) tenía 0 documentos. La bóveda ya contiene notas `Procesos/**/*.md` con pasos, decisiones, motivos y límites.

## Alternativas
- Inyectar las notas como `contextual_update` al conectar: sin tocar el agente, pero solo desde la app y con tamaño limitado.
- Herramienta de servidor/MCP que consulte la bóveda: necesita URL pública.
- Subir un documento por sesión: más documentos que limpiar; un documento compilado basta para el MVP.

## Decisión
`server/tutorKnowledge.mjs` compila las notas `tipo: proceso` (sin registros vacíos ni la demo sintética; una copia por sesión, la más reciente) quitando imágenes, enlaces de fuente y la lista de revisión. Si el contenido cambió (SHA-256), crea un documento de texto en la base de conocimiento, lo adjunta al tutor (`usage_mode: auto`) conservando los demás documentos, verifica que el prompt y el LLM no cambiaron y después borra la versión anterior. El estado queda en `Procesos/tutor-conocimiento.json` dentro de la bóveda. Corre en cada ciclo de sincronización (`VAULT_SYNC_MINUTES`) y a demanda con `npm run tutor:knowledge`.

## Consecuencias
El texto de los procesos se copia a ElevenLabs (sujeto a su retención). Lo marcado como pendiente se envía con la advertencia de no enseñarlo como regla. El tutor no aprende de sesiones que aún no tienen nota de proceso. Las conversaciones del tutor no se guardan todavía en la bóveda. Respaldo de la configuración previa del tutor en `.userhelper-backups/` de la bóveda.

## Impacto ontológico
Materializa la relación `tutor uses work_map`: el tutor consume las notas de proceso de la bóveda como conocimiento. Sin cambio en `ontology.json`.

## Verificación
Real: 4 procesos (4,887 caracteres) subidos y adjuntos; prompt idéntico; segunda pasada «unchanged». Conversación de prueba por texto (`conv_1701m42qehmxfyd8355eg7zdt7kw`): ante una OC nueva de 35 días «urgente», el tutor respondió que no la aprobara (máximo 30 días) y pidió el correo del director de finanzas; rechazó la autorización telefónica. Pruebas unitarias de compilación, reemplazo, sin cambios y prompt alterado.
