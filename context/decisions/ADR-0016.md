# ADR-0016: diagramas de proceso derivados de la bóveda privada

- Fecha: 2026-10-03 (America/Mexico_City)
- Estado: aceptada para borradores navegables; amplía ADR-0011
- Autor: Codex; operador: soyabrahamarriaga-lang
- Evidencia: el usuario pidió comprobar main y la bóveda, y mapear los procesos como diagramas interactivos en UserHelper y Obsidian.

## Base comprobada y decisión

La inspección inicial de GitHub y el clon coincidió en `2393790661d968cff4c5b58bb1cbdede4821887d`, PR #13. Incluye la bóveda (PR #7), OCR (PR #9), arranque de demo y mejoras de turnos. La bóveda local estaba configurada y tenía transcripciones y eventos, sin mapas. Se trabaja desde esa base en `codex/process-flow-maps`.

Cada conversación archivada produce un borrador de diagrama a partir de su Markdown y eventos existentes. UserHelper presenta una lista privada y un explorador React Flow cargado bajo demanda; Obsidian recibe un archivo JSON Canvas. Cada nodo conserva referencias estables al texto atribuido y al momento. No se envían transcripciones a otro proveedor ni se modifica el agente remoto.

La extracción es determinista y conservadora: conserva pasos narrados, preguntas, observaciones y posibles decisiones/reglas. Solo dibuja alternativas automáticas para la forma explícita «Si condición, acción; si no, alternativa» (y conectores equivalentes soportados). Las conexiones temporales se dibujan discontinuas; no afirman causalidad. Las razones se extraen de conectores explícitos en palabras de la persona. La proximidad de OCR es contexto, no prueba de intención. Todos los mapas mantienen estado borrador, sin inventar teach-back ni validación.

## Alternativas y consecuencias

- Solo Mermaid: facilita lectura estática, pero no ofrece el recorrido y panel de evidencia buscados. React Flow y Canvas ofrecen selección, desplazamiento y zoom.
- Extraer semántica mediante otro modelo/API: necesitaría configurar proveedor, privacidad, costo y evaluación adicional. Esta entrega deriva un borrador local y documenta su alcance; no afirma comprensión semántica general.
- Cambiar Data collection/prompt del agente: interferiría con el trabajo del equipo y conversaciones en curso. Se conserva la configuración remota.
- Un archivo dentro del repo público: descartado; las transcripciones y los mapas derivados permanecen en la bóveda privada.

Se escriben `process-flow.json`, `flujo.canvas`, `evidencia-flujo.md` y `mapa-generado.md` junto a la transcripción. No se reemplaza `work-map.md` manual. Huellas de fuente evitan reescrituras innecesarias; huellas de Canvas detectan cambios de Obsidian y los conservan. UserHelper muestra el borrador actual y ofrece descargar otro Canvas: los cambios manuales de Obsidian no se importan de vuelta. Mover nodos en UserHelper es navegación temporal, no edición persistida de conocimiento.

Importaciones por app, webhook y sincronización generan mapas. Un comando local y la lista de procesos cubren sesiones anteriores. Una falla del mapa no deshace una transcripción guardada y se informa por separado. Los endpoints nuevos usan POST con JSON para conservar el control de Origin ya existente; este control local no equivale a autenticación por persona.

## Ontología y límites

Se añade `process_flow_draft`: representación derivada y navegable de la evidencia. No equivale al Work Map validado del brief. La unidad actual es una conversación archivada; separar varios procesos dentro de ella es una tarea futura. Se conservan transcripciones y eventos originales. Hasta 180 momentos en la vista evitan diagramas inoperables; toda la evidencia se conserva en notas. La retirada de datos debe incluir derivados y Canvas editados. Versión ontológica 1.

## Validación

Pruebas de evidencia, ramas explícitas, ausencia de palabras del experto, referencias estables, formato Canvas, regeneración/idempotencia, concurrencia, rechazo de rutas/symlinks y conservación de notas y Canvas manuales. Pruebas HTTP de importación/listado/lectura/origen; compilación; revisión de interacción y dispositivos. Los resultados concretos se registran en la bitácora del aporte.
