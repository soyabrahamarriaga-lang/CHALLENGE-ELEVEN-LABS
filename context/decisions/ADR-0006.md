# ADR-0006: Acceso directo a ElevenLabs mediante MCP remoto y OAuth

- Fecha: 2026-10-03
- Estado: aceptada la vía de acceso; autenticación pendiente
- Autor: Codex; operador: soyabrahamarriaga-lang
- Evidencia: el usuario pidió acceso directo, descartó operar por navegador y propuso MCP. La documentación oficial de ElevenLabs describe el servidor remoto con OAuth; el anterior servidor local está deprecado.

## Decisión y razón

Conectar Codex al MCP oficial remoto. Para verificar recursos, solicitar `convai_read`. La autorización la completa el usuario en ElevenLabs, escogiendo el workspace. El navegador solo interviene en ese consentimiento; las consultas posteriores usan MCP. No crear credenciales API para resolver una conexión que admite OAuth.

La URL genérica documentada fue rechazada por Codex porque los metadatos de ElevenLabs declaraban el recurso `https://api.us.elevenlabs.io/v1/mcp`. Configurar ese recurso declarado en vez de desactivar la comprobación. Las fuentes y el procedimiento reproducible están en `docs/READINESS.md`.

## Alternativas y consecuencias

El acceso REST con API key se conserva como alternativa opcional de lectura, con un script sin dependencias y pruebas de manejo de secretos. No se ha autenticado ni sustituye MCP. La vía antigua `uvx elevenlabs-mcp` requiere instalación y credenciales y ya está deprecada, por lo que no se instala.

Cada persona/cliente conecta su propia sesión al workspace. Configuración local y credenciales OAuth permanecen fuera de Git; el repositorio comparte el procedimiento, el estado y la evidencia sin secretos. Registrar el servidor no equivale a autenticarse; autenticarse no prueba que exista un agente ni que los permisos permitan modificarlo. La inspección de lectura no inicia desarrollo ni consumo de audio.

## Impacto ontológico

Separar cliente MCP (Codex/Claude), servidor de herramientas, workspace, permiso de acceso, agente conversacional y modelos que utiliza. Ninguno de los primeros implica por sí solo un agente de producto configurado. No cambia la ontología del AI Apprentice.

## Verificación

Configuración TOML válida, metadatos oficiales inspeccionados y flujo OAuth iniciado con `convai_read`. Pendiente: consentimiento del usuario y llamada MCP de lectura. Las pruebas del inspector REST solo validan respuestas simuladas; no acreditar acceso real con ellas.
