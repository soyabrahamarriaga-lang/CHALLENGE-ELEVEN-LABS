# ADR-0008: UserHelper, prototipo frontend antes de integrar IA

- Fecha: 2026-10-03
- Estado: aceptada para esta fase; no sustituye los mínimos del challenge
- Autor: Codex; operador: soyabrahamarriaga-lang
- Evidencia: solicitud de frontend aportada directamente por el usuario y confirmaciones de React + TypeScript, nombre UserHelper y diseño delegado para construir directamente.

## Problema y decisión

El equipo necesita recorrer la transferencia de experiencia entre senior e intern y compartir una base de interfaz mientras decide e integra el agente. Implementar una aplicación Vite con React y TypeScript estricto, componentes por funcionalidad, datos sintéticos y adaptadores locales. No acoplar esta fase al bloqueo de autenticación MCP ni presentar simulaciones como capacidad real de ElevenLabs.

La conexión y la sesión son estados independientes. Iniciar exige conexión y consentimiento de demostración; una desconexión pausa la sesión; reconectar no autoriza reanudar. Los fragmentos ficticios excluidos se retiran del proceso de ejemplo guardado. El mapa conserva acción, propósito, razón atribuida, decisión, variante y momento de navegación.

## Alternativas y consecuencias

- Integrar voz, captura y backend primero: retrasa la revisión de la experiencia solicitada y amplía el alcance autorizado de esta fase.
- Mock estático: permite revisar apariencia, pero no consentimiento, pausas, errores ni relación entre mapa y reproducción.
- React + Vite sin backend: permite revisar esos comportamientos y mantener una frontera de integración explícita. Las sesiones y marcadores se conservan solo en localStorage; no hay colaboración multiusuario real ni autenticación en la aplicación.

El contador de llamada demo mide el tiempo activo. El reproductor utiliza una duración mínima de muestra para que los pasos sean navegables incluso tras una demo muy corta; la descripción distingue ambas duraciones. No existe archivo de audio/video ni transcripción generada.

## Ontología e invariantes

Una sesión de demostración no constituye evidencia del experto. Se añaden al modelo conexión, sesión demo y variante contextual, conservando los conceptos del brief. Revisar un recorrido no acredita dominio. Un selector de perfil no otorga permisos reales. Los ejemplos de soporte, operaciones y marketing ilustran UI, sin decidir el caso final del challenge.

## Validación y siguiente paso

Pruebas del reducer y almacenamiento, build estricto y recorrido de navegador; los resultados observados quedan en la entrada del aporte y docs/FRONTEND-PROTOTYPE.md. CI ejecuta las pruebas frontend y build dentro del check protegido existente. Después: elegir caso real, conectar voz y eventos de pantalla, debrief/teach-back, revisión del experto y Teach sobre caso nuevo.
