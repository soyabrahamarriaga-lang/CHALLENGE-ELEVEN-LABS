# ADR-0014: Inicio del agente sin código de equipo en la demo local

- Fecha: 2026-10-03
- Estado: aceptada
- Autor: Claude; operador: soyabrahamarriaga-lang
- Relación: modifica ADR-0010 solo cuando `AGENT_OPEN_ACCESS=true`

## Problema y evidencia
El usuario pidió iniciar la conversación con el agente «rápidamente sin tener que poner códigos». ADR-0010 reutilizó `LIVEKIT_JOIN_CODE` como barrera de `/api/elevenlabs/session` porque ese endpoint emite accesos con la API key del proyecto (consume créditos). En la demo el backend escucha en `127.0.0.1` y exige el origen exacto de la app.

## Alternativas
- Mantener el código: fricción en cada demo; el usuario lo rechazó.
- Recordar el código en el navegador: sigue pidiéndolo la primera vez y guarda un secreto en localStorage.
- Quitar el código siempre: expondría los créditos si se publica la app.

## Decisión y razón
`AGENT_OPEN_ACCESS=true` (solo ese valor exacto) permite iniciar el agente sin código. `/api/elevenlabs/status` informa `requiresCode` y la UI oculta el campo. Se mantienen origen exacto, `Sec-Fetch-Site`, JSON, consentimiento, límite de intentos y cuerpo máximo. La videollamada LiveKit sigue exigiendo su código. Por defecto (`false` o ausente) nada cambia.

## Consecuencias
Cualquiera que alcance el backend con el origen permitido puede iniciar conversaciones a costa de la cuenta. Seguro en loopback; el backend avisa al arrancar si el modo está activo y escucha fuera de loopback. Antes de publicar, quitar la variable.

## Impacto ontológico
Ninguno.

## Verificación
Prueba: con el modo activo, status `requiresCode:false`, sesión 200 sin código, 403 con otro origen, 400 sin consentimiento, LiveKit 401 sin código; con un valor distinto de `true`, 401.
